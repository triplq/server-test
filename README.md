**Клиент-сервер на QT**

Сервер хранит пользователей в SQLite и обслуживает нескольких клиентов одновременно. Клиент — оконное приложение на Qt Widgets.

Папки: `server/` и `client/`, у каждой свой CMakeLists.txt.

**Что нужно**

- CMake 3.19 или новее
- Qt 6.5 или новее (Core, Network, Sql, Widgets)
- драйвер SQLite для Qt (в обычной установке Qt он есть)

**Сборка**

Через Qt Creator: откройте `server/CMakeLists.txt` и `client/CMakeLists.txt`, соберите оба проекта.

**Запуск**

Сначала запускается сервер, потом клиент (клиентов можно открыть несколько). Сервер слушает порт 2323, клиент подключается к 127.0.0.1(localhost):2323. Если сервера нет, клиент сам пробует подключиться каждые 3 секунды.

База лежит в файле `data/app.db` рядом с исполняемым файлом сервера. При каждой сборке сервера туда копируется пустая база из `server/data`, поэтому после пересборки пользователи пропадают. Условное решение для теста, так-то можно сделать PostgreSQL на сервере.

**Как пользоваться**

- На первой странице выбираем Sign Up или Log In.
- Sign Up: вводим имя и email, жмём OK. Пользователь добавляется в базу, открывается страница со списком. 
- Log In: вводим имя и email уже зарегистрированного пользователя. Пароля нет, проверяется только что такая пара есть в базе.
- На странице пользователей высвечивается сообщение в statusBar, кнопка Get загружает список с сервера в таблицу.
- Если пользователь уже есть или нет связи с сервером, показывается окно с ошибкой.

**Протокол**

Обмен по TCP в рамках библиотек QTcpSocket QTcpServer. Каждое сообщение — это 4 байта с длиной (BigEndian) и затем JSON. Так пишет `QDataStream` при отправке `QByteArray`.

В каждый запрос клиент добавляет число `id` (HTTP/2.0 stream id), сервер возвращает его в ответе. По нему клиент понимает, на какой запрос пришёл ответ, если запросов отправлено несколько.

Добавить пользователя:

```
{ "action": "add_user", "username": "Sidorov", "email": "sidorov@example.com", "id": 1 }
{ "status": "success", "message": "User added successfully", "id": 1 }
```

Проверить пользователя (вход):

```
{ "action": "login_user", "username": "Sidorov", "email": "sidorov@example.com", "id": 2 }
{ "status": "success", "message": "User login successfully", "id": 2 }
```

Получить список:

```
{ "action": "get_users", "id": 3 }
{ "status": "success", "message": [ { "username": "Sidorov", "email": "sidorov@example.com" } ], "id": 3 }
```

При ошибке `status` равен `failure`, а в `message` текст ошибки, например `User does exists`.

**Многопоточность**

Сервер: каждый запрос выполняется в отдельной задаче пула потоков (QThreadPool), максимум единовременных потоков - 64. Внутри задачи открывается своё подключение к базе, ответ отправляется клиенту из главного потока.

Клиент: интерфейс работает в главном потоке, а работа с сетью вынесена в отдельный QThread и связана с интерфейсом сигналами и слотами, поэтому окно не зависает.
